# 连接真实 iPhone（第七阶段）

聆聆是网页，不能直接操作其他 App。真实 iPhone 上的操作全部通过 **你自己在「快捷指令」App 中创建、并在聆聆中登记的快捷指令** 完成；
聆聆通过 `shortcuts://x-callback-url/run-shortcut` 链接运行它们，每一次都要你先点「打开快捷指令」。

不越狱、不使用私有接口、不查看屏幕、不读取其他 App 的数据、不模拟点击。

## 桥接基础（PR A）

| 模块 | 作用 |
| --- | --- |
| `src/ios/env.ts` | 检测 iPhone / iPad、系统版本、Safari / 主屏幕 App / 其他 App 内置浏览器。网页无法知道快捷指令是否已安装，只能显示「可以尝试（需要测试）」 |
| `src/ios/shortcuts.ts` | 白名单（settings `ios-shortcuts`，随设置进入备份）、参数清理（去控制字符和隐藏方向字符、限长）、链接构造（全部参数 URL 编码）、回跳解析 |
| `src/ios/runs.ts` | 运行记录与状态（Dexie v10 只新增 `shortcutRuns` 表，不进入备份） |
| `src/ios/incoming.ts` | 打开聆聆时处理回跳并立即从地址栏去掉参数 |
| 「我的 → 连接真实 iPhone」 | 环境检查、说明、创建步骤、登记、测试连接、最近的运行、角色权限入口 |

### 状态

| 状态 | 含义 |
| --- | --- |
| 等待确认 | 还没有打开快捷指令；取消则什么都不会发生 |
| 已发起 | 已请求打开快捷指令，还不知道结果 |
| 已确认完成 | 快捷指令通过 x-success 回跳，且运行 ID 与校验码正确 |
| 无法验证 | 回到聆聆 10 秒仍没有回跳，或页面根本没有切换走（例如在「是否打开」时点了取消），或发起 3 分钟后仍没有回跳 |
| 执行失败 | x-error 回跳（显示快捷指令给的原因） |
| 已取消 | 确认前取消，或 x-cancel 回跳，或你标记「没有完成」 |
| 你确认已完成 | 你点了「我在 iPhone 上看到了」；与系统回报分开显示 |

- 没有可靠结果时只会显示「已发起 / 无法验证」，**不会显示成功**
- 「打开快捷指令」在点按事件中**同步**打开链接（iOS 只允许用户操作直接打开其他 App），并立即同步写下标记；页面被挂起后回来再补写
- 回跳必须带正确的校验码，每次运行只处理一次；重放、伪造的回跳都会被忽略
- 连点按钮只打开一次；同样内容 10 分钟内只执行一次（`recentDuplicate`，PR B / D 使用）

### 已知 iOS 限制（需要真机确认）

1. **主屏幕 App 与 Safari 数据不共享**：从主屏幕打开聆聆时，快捷指令的回跳会打开 Safari，Safari 里找不到这次运行 → 原来的地方显示「无法验证」，需要你手动确认。**建议在 Safari 中使用这些功能**
2. Safari 每次打开快捷指令前会询问「是否在快捷指令中打开」
3. 回跳时快捷指令追加 `result` 的方式（`?` 或 `&`）各版本可能不同，解析时两种都兼容
4. 快捷指令首次运行某些操作（如提醒事项、日历）时会请求系统权限，需要你在 iPhone 上允许
5. 回跳会在 Safari 中打开一个新标签页；状态会同步到原来的标签页（同一浏览器的数据是共享的）

## 提醒事项、系统日历、打开应用（PR B）

`src/ios/actions.ts`：先生成**执行计划**（具体日期、星期、时间、标题），显示给你，点「打开快捷指令」后才运行。

| 操作 | 快捷指令 | 传入内容（JSON 文本） | 说明 |
| --- | --- | --- | --- |
| 提醒事项 | 「聆聆提醒事项」 | `{"v":1,"type":"reminder","title","due":"YYYY-MM-DD HH:MM","notes"}` | 没写时间默认 09:00；已经过去的时间拒绝 |
| 系统日历 | 「聆聆日历」 | `{"v":1,"type":"calendar","title","start","end","location","notes"}` | 没写结束时间默认 1 小时；跨午夜自动到第二天；**不写入聆聆自己的日历** |
| 打开应用 | 不需要 | `x-apple-reminderkit://` `calshow://` `shortcuts://` `maps://` `music://` `mobilenotes://`；Safari 只能打开 https 网址（新页面） | 这些链接是否在每个 iOS 版本可用需要真机确认 |
| 自定义 | 你登记的 | 可选的一段文字 | 第三方 App：在快捷指令中用「打开 App」做一个快捷指令，再登记为自定义 |

- 「我的 → 连接真实 iPhone → 试一试真实操作」可以不经过 AI 直接运行
- 同样内容 10 分钟内只能发起一次，除非你勾选「我确定要再执行一次」；双击「打开」只打开一次
- 计划里写明「会保存到 iPhone 的提醒事项 / 系统日历，不是聆聆」
- 只有快捷指令回跳成功才显示「已确认完成」；出错回跳显示「执行失败」与原因
- 已知限制：
  - 快捷指令「从输入中获取日期」对 `YYYY-MM-DD HH:MM` 的识别需要真机确认
  - 本版本日历事件必须有开始时间（暂不支持全天事件）
  - 「打开 App」操作不能用变量选择应用，所以第三方 App 要逐个做快捷指令

## 从 iPhone 分享到聆聆（PR C）

网页不能注册成原生的分享扩展。做法是：**iOS 分享菜单 → 你创建的快捷指令 → 打开聆聆网页**。

| 内容 | 快捷指令 | 传递方式 |
| --- | --- | --- |
| 文字、网页链接 | 「分享到聆聆」 | URL 编码后放在 `#lingling_share=1&t=` 之后（`#` 后面的内容**不会发送到服务器**，也没有服务器的长度限制）；最多 4000 字，超出截断并提示 |
| 图片 | 「图片发到聆聆」 | 不放进链接。快捷指令「拷贝到剪贴板」，聆聆打开后点「粘贴图片」（只在本机处理），或「从照片中选择」 |
| 文件信息 | 「文件信息发到聆聆」 | 只传文件名与大小，不传文件内容 |

- 进入聆聆后先显示**预览**：保存为便签 / 放进和某个角色的输入框（**不会自动发送**）/ 复制 / 丢弃；图片确认后才保存到相册
- 不会自动发给 AI；含有证件号、银行卡号、密码、密钥时显示红色提醒，健康 / 财务 / 住址类显示黄色提醒
- 内容只暂存在当前页面（sessionStorage），丢弃或处理后清除
- 测试中发现并处理的问题：
  - 4000 个汉字放在 `?` 后面时地址约 37 KB，会被服务器拒绝，所以改为放在 `#` 后面
  - 聆聆已经打开时，Safari 可能只改变 `#` 后面的内容而不重新加载页面，所以运行中也会接收分享内容

### 已知限制
- 打开的是 Safari，不是主屏幕 App（iOS 不允许快捷指令指定打开主屏幕 Web App）
- 图片粘贴需要你在 iPhone 上点「允许粘贴」；iOS 版本较旧时可能不支持读取剪贴板图片，可用「从照片中选择」

### 真机验收（PR C）
- [ ] S1 按步骤创建「分享到聆聆」，在 Safari 网页上点分享 → 「分享到聆聆」→ 聆聆显示链接预览
- [ ] S2 在备忘录中选中一段文字分享 → 预览 → 保存为便签 → 便签应用中出现
- [ ] S3 分享 → 放进和角色的输入框 → 聊天输入框中有内容，**没有自动发送**
- [ ] S4 创建「图片发到聆聆」，在照片中分享一张 → 粘贴图片 → 保存到相册
- [ ] S5 分享一段很长的文字（超过 4000 字）→ 显示截断提示

## AI 工具调用与权限联动（PR D）

复用第六阶段的工具注册、权限、确认与执行记录。工具名称是聆聆的接口名，**不是 iOS 原生 API**，具体执行由快捷指令完成。

| 工具 | 权限（默认关闭） | 说明 |
| --- | --- | --- |
| `ios.create_reminder` | iPhone 提醒事项 | `title` `date` `time?` `notes?` |
| `ios.create_calendar_event` | iPhone 系统日历 | `title` `date` `startTime` `endTime?` `location?` `notes?`；不是聆聆的日历 |
| `ios.open_app` | 打开 iPhone 应用 | `app` 只能是列表中的值；`safari` 需要 https 网址 |
| `ios.list_shortcuts` | 运行自定义快捷指令 | 只列出你允许 AI 使用的 |
| `ios.run_shortcut` | 运行自定义快捷指令 | 只能运行白名单中、且勾选了「AI 可用」的 |

- **所有 iPhone 操作每一次都要确认**（即使「允许·逐次确认」），卡片显示执行计划
- 卡片出现前就生成「等待确认」的运行；**「确认并打开」在点按中直接打开快捷指令**（iOS 只允许用户点按打开其他 App）
- 拒绝、停止生成、撤销权限：卡片立即消失，运行被取消，什么都不会打开
- 结果如实交还模型：只有快捷指令回跳成功时 `status: confirmed, verified: true`；否则是 `launched` / `unverifiable`，系统提示要求模型只能说「已经发起，请在 iPhone 上看一下」
- 聊天中按时间插入运行状态卡片（已发起 / 已确认完成 / 无法验证 / 执行失败 / 已取消），回跳在 Safari 新标签页中处理后，原来的聊天标签页同步更新
- 防重复：同样内容 10 分钟内只能发起一次；一次回复最多一个 iPhone 操作；连点只打开一次
- 防注入：严格参数校验（多余参数、非法日期、未知应用都拒绝）；模型不能传链接或快捷指令以外的名称；JSON 由程序生成
- 只有提供了工具时，系统提示里才会加入当前日期时间（换算「明天」「下周五」）
- 执行记录（我的 → AI 工具权限）中可以看到每次 iPhone 操作与状态

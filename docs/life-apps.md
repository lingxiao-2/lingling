# 生活应用（V1 第五阶段）

## PR A：相册

入口：桌面「相册」图标（`#/album`）。

| 功能 | 说明 |
|---|---|
| 导入 | 右上角图片按钮，从 iPhone 相册或「文件」选择，可多选（一次最多 60 张）。逐张在本机处理，不并发，避免 iPhone 内存紧张 |
| 格式 | JPEG、PNG、WebP、GIF，以及浏览器能解码的 HEIC/HEIF。解码失败的逐张列出原因（HEIC 会提示改用 Safari 或「兼容性最佳」），**不会假装导入成功** |
| 处理 | 显示图最长边 2048 px（JPEG，质量 0.88；带透明的小 PNG 保持 PNG）；缩略图最长边 360 px，用于网格，滚动时不读原图 |
| 相册 | 全部照片、自建相册、最近删除；新建、重命名、删除相册（照片不删除，回到全部照片）；选择多张移动到相册 |
| 查看 | 全屏查看；双指缩放、拖动、双击放大 / 还原；未放大时左右滑动切换上一张 / 下一张 |
| 信息 | 名称和备注可编辑；导入时间、尺寸、保存大小、原始文件大小与格式、所在相册 |
| 删除 | 先进入「最近删除」，可以恢复；只有在「最近删除」中确认后才会彻底删除（原图一起删除） |
| 搜索 | 名称与备注，多个关键词需要全部命中 |
| 存储 | 显示照片占用和浏览器允许的空间；已用超过 80% 或照片超过 500 MB 时提醒 |
| 隐私 | 照片只保存在本机 IndexedDB，不会上传（浏览器测试中确认没有任何外部请求） |

**数据库**：Dexie v4 → v5，只新增 `albums`、`photos`（信息与缩略图）、`photoBlobs`（原图 Blob）三张表，不修改、不删除已有的表。迁移测试确认旧的角色、聊天和 API Key 原样保留。原图与信息分表，列表不会读取原图。

**备份**：PR E 起，备份包含照片原图（见下文「PR E」）。

**预留给下一阶段的接口**（`src/life/albumAccess.ts`，本阶段没有任何 AI 调用）：相册列表、照片元数据（不含图片内容）、获取用户明确授权的指定照片原图。最近删除的照片不会出现。

**测试**
- `scripts/test-album.ts`（npm test）：格式预检、缩放尺寸、搜索、存储提醒、相册与照片的增删改移、最近删除与恢复、只能彻底删除已在最近删除中的照片、v4→v5 迁移保留旧数据和 API Key、预留访问接口的授权规则。
- `scripts/e2e/album.cjs`（本地，Chromium 模拟 iPhone 13，20 项）：从桌面打开、导入 3 张真实图片 + 1 张 HEIC + 1 张损坏的 JPEG（Chromium 不能解码 HEIC，正好验证明确报错）、大图压缩到 2048、缩略图很小、新建相册、搜索、选择移动、双击放大 / 还原、左滑切换、备注保存后刷新仍在、删除与恢复、没有任何外部请求。

## PR B：日记

入口：桌面「日记」图标（`#/diary`）。

| 功能 | 说明 |
|---|---|
| 写日记 | 日期（可改成任意一天）、心情（平静、开心、温柔、期待、想念、疲惫、低落、不安）、标题、正文、标签 |
| 自动保存 | 停顿约半秒后自动保存，离开页面时立即保存，顶部显示「已自动保存 hh:mm」。**空白的新日记不会保存** |
| 查看 | 列表按日期从新到旧排列；顶部月历（有日记的日子带小点），点日期按天查看，可以「写这一天」 |
| 搜索与筛选 | 全文搜索（标题、正文、标签、心情），常用标签一键筛选 |
| 照片 | 从相册选择照片关联（稳定 ID）；照片被删除后显示「照片已删除」，日记照常打开；点照片看大图，关闭后回到日记 |
| 删除 | 进入「最近删除」，可以恢复；只有在最近删除中才能彻底删除 |
| 隐私 | 每篇日记都有「允许 AI 读取」开关，**默认关闭**。目前没有任何 AI 读取日记，也不会把日记变成角色记忆 |
| 风格 | 半透明信纸，衬线大号日期，正文 30 px 行距配淡横线，16 px 字号（iPhone 输入时不会放大页面） |

**数据库**：v5 → v6，只新增 `diaries` 一张表。

**预留接口**（`src/life/diaryAccess.ts`，本阶段没有任何 AI 调用）：只返回勾选了「允许 AI 读取」且不在最近删除中的日记；取消勾选后立即不可读。

## PR C：便签

入口：桌面「便签」图标（`#/notes`），或点桌面上的便签小组件。

| 功能 | 说明 |
|---|---|
| 两种模式 | 文字 / 清单，可以互相转换（文字每行变成一项；清单每项变成一行）；清单回车新增一项，可勾选完成 |
| 自动保存 | 停顿后自动保存，离开时立即保存；空白的新便签不保存 |
| 置顶与颜色 | 置顶的排在最前；6 种颜色（珍珠白、冰蓝、雾蓝、淡紫、樱粉、薄荷） |

## PR D：日历

入口：桌面「日历」图标（`#/calendar`）。

| 功能 | 说明 |
|---|---|
| 月视图 | 前后切换月份；有日程的日子标蓝点，有日记的日子标淡紫短线；点日期查看当天的日程和日记 |
| 日程 | 未来 60 天按日期分组列出 |
| 新建 / 编辑 | 标题、类型（日程 / 纪念日 / 生日）、全天、日期、开始与结束时间、重复（不重复 / 每天 / 每周 / 每月 / 每年）、地点、备注；保存前校验（结束不能早于开始等），不合法不保存 |
| 重复 | 只保存一条，显示时按规则计算；某月没有 31 日、非闰年没有 2 月 29 日时那一次跳过 |

## PR E：应用整合

### 备份与恢复（备份格式 v2）
- 全部数据备份现在包含**相册、照片、日记、便签、日程**。
- **照片原图作为单独的图片文件**打包进备份：有照片时备份是 ZIP（`backup.json` + `photos/<照片ID>`，文件名仍为 `.lingling`），不会把图片塞进一条巨大的 JSON。ZIP 用「存储」方式，不压缩（照片本身已经压缩过），逐张读取。
- **生成前估算体积**，备份页显示照片张数和大小；超过 300 MB 时提醒 iPhone 可能内存不足。可以选择「不包含照片」：这时照片信息也不放进备份，避免只有信息没有原图的照片。
- **恢复**：同时支持旧的 JSON 备份（v1）和新的 ZIP 备份（v2）。读取 ZIP 时校验每张照片文件存在且大小一致，缺失或损坏时明确报错。
- **「完全替换」只清空备份里包含的类别**：用旧版备份（没有日记、相册等）替换恢复时，不会清空生活应用的数据；全部数据备份会记下空的类别，替换时这些类别会被清空。照片信息被替换时，原图一起替换。
- **「合并（保留本机）」不会覆盖本机已有的照片原图。**
- 恢复在**一个事务里**完成，中途任何一步失败都整体回滚，本机数据保持原样（有测试）。
- 来自更新版本的备份会被拒绝。不改变现有 API Key 的处理（默认不导出，恢复时不会用空值覆盖本机的 Key）。

### 统一数据服务层（为第六阶段 AI 工具调用准备）
`src/life/service.ts`，**本阶段没有任何 AI 调用**：
- 工具定义 `LIFE_TOOLS`（带 JSON Schema 参数）：`query_diaries`、`query_notes`、`query_calendar`、`query_album`、`create_note_draft`、`create_event_draft`。
- **授权开关默认全部关闭**（settings `life-access`，只认明确为 true 的值，数据损坏时一律当作关闭）。未授权时工具返回「用户没有授权这项访问」，不读取任何数据。
- 只读工具只返回必要字段：日记只返回逐篇勾选了「允许 AI 读取」的；相册只返回元数据，不含图片；最近删除的内容永远不返回；日历一次最多查一年。
- 写入类工具**只能创建草稿**（settings `life-drafts`），用户在「我的 → 生活应用的 AI 权限」确认后才会变成真的便签 / 日程，也可以拒绝。
- 页面「我的 → 生活应用的 AI 权限」：查看和修改这些开关（默认全部关闭），处理等待确认的草稿，并明确写明目前没有任何 AI 使用这些权限。

### 跨应用关联
所有关联都用稳定 ID：日记 → 照片、日程 → 日记、日程 → 角色、桌面小组件 → 便签。被引用的内容删除后，引用方照常读取，界面显示「已删除」（有测试覆盖照片、日记、角色、便签被删除的情况）。

### CI 修复（单独的 PR #36）
所有 CI 运行原来共用一个会互相取消的并发组，PR 的检查曾把 main 的发布标记为「已取消」。现在每个分支 / PR 各自一组，发布任务排队进行，不再被取消。#35 合并时，PR #37 的检查和 main 的发布同时运行，发布正常完成。

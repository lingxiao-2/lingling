# 表情包：通过链接导入

## 现在的做法：浏览器直接读取
- 聆聆是纯前端应用，链接由**你的浏览器直接请求**，不经过任何聆聆服务器或第三方代理。
- 请求不带登录状态（`credentials: omit`），也不带来源信息（`no-referrer`）。
- 文件类型按内容判断：先看文件头是否为 PNG / JPEG / WebP / GIF，再看是否为 ZIP，最后看是否为 HTML 网页。不看扩展名，也不看 Content-Type。
- 限制：

  | 项目 | 上限 |
  |---|---|
  | 单张图片 | 5 MB |
  | ZIP | 60 MB |
  | 网页 | 3 MB |
  | 超时 | 20 秒 |
  | 跳转 | 跟随，但跳转后的地址要重新校验 |

  下载时边读边计数，超过上限立即停止。ZIP 解压沿用本地导入的上限：最多 600 个文件、总大小 200 MB、压缩比不超过 60。
- 拒绝的地址：本机、内网、链路本地、云元数据（如 169.254.169.254）、`.local` / `.internal` 域名、带用户名或密码的链接、非 http / https 协议。
- 网页提取（尽力而为）：
  - 只看 `<main>` 或 `<article>`；都没有时看 `<body>`，并去掉页头、页脚、导航和侧栏。
  - 图片地址读取 `src`、`data-src`、`data-original`，以及 `srcset` 中最大的一张。
  - 也读取指向图片或 ZIP 的 `<a>` 链接。
  - 过滤头像、logo、图标、广告、二维码、小于 48px 的图、SVG 和 data: 地址。
  - 用户在预览中自己勾选要导入哪些。
  - 用脚本动态加载图片的页面，通常识别不到。

## 为什么 Safari 能打开图片，聆聆却读不到（以 i.imgant.com 为例）
- 在 Safari 地址栏打开图片，或者用 `<img>` 显示图片，**不受跨域限制**：浏览器只是把图片画出来，网页脚本拿不到图片的内容。
- 聆聆导入时要拿到图片的**字节**，才能计算哈希、生成缩略图、保存到本机，所以必须用 `fetch()` 读取。
- 跨域读取要求源站在响应里返回 `Access-Control-Allow-Origin`。源站没有返回时，浏览器会拦下这次读取，只告诉网页「Load failed / Failed to fetch」。
- 浏览器不会告诉网页具体原因：跨域、断网、证书错误、被拦截，在网页看来都一样。所以聆聆无法从这一个错误里读出准确原因。
- 很多国内图床和平台 CDN 默认不返回这个响应头，所以会出现「Safari 能看，聆聆读不到」。
- 防盗链也会导致失败（例如带了 Referer 就返回 403）。聆聆请求时**不发送 Referer**、不带 Cookie；源站真的返回 403 时，会提示「拒绝访问 / 防盗链」，不会伪造来源去绕过。

> 未验证：开发环境（云端沙盒）无法访问 i.imgant.com，没能读到它的真实响应头。上面的判断依据是你描述的现象：Safari 能打开、聆聆读取失败。最终结论以你在 iPhone 上「测试一个链接」得到的诊断结果为准，验收步骤见下文。

### 现在的诊断流程
1. 用浏览器直连（`fetch`，`credentials: omit`、`no-referrer`）。
   - http 链接会先改试 https，因为 https 页面里加载 http 内容会被拦截。
2. 直连得到真实的 HTTP 响应时，按状态码说明原因，**不再尝试代理**：
   - 401 / 403：需要登录、有权限限制或开启了防盗链。
   - 404 / 410：文件不存在或链接已失效。
   - 429：访问过于频繁。
   - 其他：显示具体的状态码。
3. 直连被浏览器拦下时，用 `<img>`（no-referrer）再加载一次：
   - **能显示** → 结论是跨域限制（CORS）。提示两个办法：长按保存到相册后导入，或者配置你自己的图片代理。
   - **也打不开** → 链接失效、开启了防盗链或网络不通。短链接、App 分享页、网盘有各自的专门提示。
4. 配置了图片代理时，改由代理下载，并把代理返回的错误码换成具体原因。
5. 失败时，界面会列出每一步的结果，也就是诊断过程。

## 自己部署的图片代理（可选，代码在 `proxy/link-proxy-worker.js`，**未部署**）
### 能做什么，不能做什么
- 能：下载**公开的** https 图片（PNG / JPEG / WebP / GIF）和 ZIP。浏览器因为跨域读不到的这类资源，可以改由代理下载。网页提取同样可以经过代理。
- 不能：
  - 需要登录、验证码或付费的内容。
  - 必须带上原站 Referer 才给的资源：代理不伪造 Referer。
  - 由脚本动态加载的分享页。
  - http 链接。
  - 内网地址。

### 安全设计
| 风险 | 做法 |
|---|---|
| 被别人当作免费代理 | 只接受 `ALLOWED_ORIGINS` 里的网站来源，并要求访问口令 `ACCESS_TOKEN`（Secret，只存在 Worker 里和你的设备上，**不在仓库和构建产物中**）。 |
| SSRF（访问内网） | 只允许 https 和 443 端口。拒绝 IP 字面量形式的内网地址，以及 localhost、.local、.internal 等域名。 |
| DNS 重绑定 | 先用 DNS over HTTPS 解析 A 和 AAAA 记录，**任何一个**结果是内网 / 保留地址就拒绝。限制：Worker 发出请求时会再解析一次，理论上仍有很短的时间窗口；Cloudflare 的出站请求本来也到不了你的内网。 |
| 恶意跳转 | 手动跟随跳转，最多 3 次，每一跳都重新做上面的校验；跳到 http 一律拒绝。 |
| 超大下载 | 先看 Content-Length，再边下边数：图片 10 MB、ZIP 60 MB、网页 3 MB，超出就中止。总超时 15 秒。 |
| ZIP 解压炸弹 | 代理**不解压**。解压在浏览器里进行，限制最多 600 个文件、总大小 200 MB、压缩比不超过 60。 |
| 内容伪装 | 按文件头判断类型，只放行图片、ZIP 和明确请求的 HTML。返回时带 `nosniff` 和沙盒 CSP。 |
| 绕过源站限制 | 不带 Cookie / Authorization / Referer。源站返回 401 / 403 / 404 / 429 时原样告知，不重试。 |
| 隐私 | 不缓存，不记录完整链接。只有你自己能看到 Worker 的日志。 |

### 费用（2026-11 查阅 Cloudflare 官方文档）
- **Workers 免费版**：
  - 每天 10 万次请求，UTC 零点重置；超出后返回 1027 错误，**不会自动扣费**。
  - 每次请求 10 ms CPU：等待网络的时间不计入，只计算校验和计数字节的时间。
  - 每次请求最多 50 次对外请求：每张图约 3 次，即 2 次 DNS 加 1 次下载，再加上可能的跳转。
- 个人导入表情包一般远低于免费额度。只有你主动升级到付费版（最低每月 5 美元）才会产生费用。
- 已知风险：
  - 下载很大的 ZIP 时，CPU 可能偶尔超过 10 ms，导致这一次失败。
  - `*.workers.dev` 在中国大陆的访问可能不稳定；需要时可以绑定自己的域名（域名要另外购买）。

### 部署步骤（全部由你自己操作；聆聆不会替你部署）
1. 注册或登录 Cloudflare，进入 **Workers & Pages → Create → Create Worker**，名字随意，例如 `lingling-link-proxy`。
2. 点 **Edit code**，把 `proxy/link-proxy-worker.js` 的全部内容粘贴进去，然后点 **Deploy**。
3. 进入 Worker 的 **Settings → Variables and Secrets**：
   - `ACCESS_TOKEN`：类型选 **Secret**，填一个足够长的随机字符串。
   - `ALLOWED_ORIGINS`：填聆聆所在的网址（只写协议和域名），例如 `https://lingxiao-2.github.io`。有多个时用英文逗号分隔。
4. 在聆聆中打开 **我 → 表情包与识图 → 链接导入代理**，填入 Worker 地址（例如 `https://lingling-link-proxy.<你的子域>.workers.dev`）和口令，然后保存。
5. 在同一页面的「测试一个链接」里输入下面的验收链接。

用命令行部署的话，可以在 `proxy/` 目录下执行：
- `npx wrangler deploy link-proxy-worker.js --name lingling-link-proxy`
- `npx wrangler secret put ACCESS_TOKEN`

`ALLOWED_ORIGINS` 在控制台的变量里添加即可。

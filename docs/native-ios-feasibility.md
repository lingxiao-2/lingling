# 原生 iOS 可行性报告（第七阶段附带，简版）

聆聆目前是网页（Safari / 主屏幕 Web App）。本阶段**没有**编写原生 App。下表区分四类能力。

## 1. 现在的 Web App 就能做到

| 能力 | 说明 |
| --- | --- |
| 打开快捷指令 / 自带 App 的公开链接 | `shortcuts://`、`calshow://` 等，必须由用户点按触发 |
| 接收快捷指令回跳 | `x-callback-url` 回到网页（Safari 中可靠；主屏幕 App 回跳会去 Safari） |
| 本地数据 | IndexedDB；清除 Safari 数据会丢失，需要备份 |
| 选择照片 / 文件 | `<input type="file">`，用户主动选择 |
| 读取剪贴板图片 | 需要用户点「允许粘贴」 |
| Web 推送通知 | iOS 16.4+，仅限添加到主屏幕的 Web App，需要推送服务器（本项目未做，属于需要额外服务的方案） |

## 2. 需要 iOS 快捷指令支持（本阶段已实现的方式）

| 能力 | 说明 |
| --- | --- |
| 创建提醒事项、系统日历事件 | 用户自建快捷指令，聆聆传 JSON 文本 |
| 打开第三方 App | 每个 App 一个「打开 App」快捷指令 |
| 分享菜单进入聆聆 | 「在共享表单中显示」的快捷指令 → 打开网页 |
| 定时自动化 | 快捷指令「自动化」（例如每天 9 点打开聆聆），需要用户在快捷指令 App 中设置 |
| 局限 | 无法分发经审核的安装链接；不同 iOS 版本操作名称与日期识别可能不同；执行结果只能通过回跳得知 |

## 3. 需要原生 App（Swift / SwiftUI）才可能做到

| 能力 | 技术 |
| --- | --- |
| 直接读写提醒事项与日历（不经过快捷指令、能确认写入结果） | EventKit + 用户授权 |
| 出现在系统分享菜单里 | Share Extension |
| 让 Siri / 快捷指令直接调用聆聆的功能（「让沈星回提醒我……」） | App Intents（iOS 16+），可提供快捷指令操作与 Spotlight 建议 |
| 本地通知（角色定时发消息提醒） | UserNotifications，不需要服务器 |
| 访问「文件」App 中的文件、iCloud Drive | FileProvider / UIDocumentPicker / iCloud |
| 小组件、锁屏小组件、实时活动 | WidgetKit / ActivityKit |
| 后台运行（有限） | BackgroundTasks，受系统严格限制 |
| 需要条件 | Mac + Xcode 编写与构建；真机安装需要 Apple ID，上架或 TestFlight 需要 Apple 开发者计划（付费，**需要你同意后才能考虑**） |

## 4. 即使是普通原生 App 也无法做到

- 查看其他 App 的屏幕内容、读取其他 App 的私有数据
- 模拟点击、自动操作其他 App 的界面（辅助功能接口不对普通 App 开放此类控制）
- 读取微信等第三方 App 的聊天记录
- 无限制地常驻后台
- 不经用户授权访问提醒事项、日历、照片、通讯录、位置

## 建议

1. 先完成本阶段的真机验收，确认快捷指令方案在你的 iOS 版本上的实际表现
2. 如果以后需要「能确认写入结果」「出现在分享菜单」「Siri 直接调用」，再考虑一个很小的原生壳（App Intents + EventKit + Share Extension），网页内容继续复用
3. 原生方案需要 Mac 与 Xcode；是否加入付费的 Apple 开发者计划由你决定

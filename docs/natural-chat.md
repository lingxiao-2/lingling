# Natural Chat：自然聊天引擎

## 一次调用，多条消息

模型在**一次请求**中输出一组消息，不会每个气泡单独请求一次：

```
<msg>真的吗！！</msg>
<msg>我就知道你可以的</msg>
<sticker id="k1"/>
```

| 环节 | 做法 | 代码 |
|---|---|---|
| 格式 | `<msg>` / `<sticker id>` 标记，而不是 JSON。好处：流式时能逐段解析；长回答里的引号和换行不需要转义；不依赖 JSON 模式；Token 更少 | `src/services/ai/messageFormat.ts` |
| 流式 | 每收到一段就重新解析一次。已经闭合的消息算完成，正在写的那条只以纯文字显示。结尾处写到一半的标记（如 `<ms`、`<sticker id="k`）会被隐藏 | `parseReply` |
| 发出节奏 | 写完一条就保存一条，下一条按上一条的长度等待 0.42～1.5 秒。整段写完以前就能看到前几条 | `replyEngine.ts` 中的 `deliver` / `PACE` |
| 条数 | 1～5 条。流式过程中最多先发出前 4 条，第 5 条及之后等结束后合并成一条，已经显示的消息不会再被改动 | `capParts` |
| 回退 | 模型完全没按格式输出时，整段作为**一条**普通文字消息（会去掉「名字：」前缀和多余空行） | `parseReply` 的 plain 模式 |
| 容错 | 能处理漏写结束标记、标记外的零散文字、表情包写在 `<msg>` 里面这几种情况 | 同上 |
| 不重复 | 每条消息的 ID 由「本次回复 ID + 序号」决定，同一条再保存一次只会被跳过 | `savePart` |
| 停止 | 已经写完的消息，加上正在写的那一条，都立即保存，不再等待节奏 | `stopReply` → `flushers` |
| 出错 | 已经写完的消息保留，写到一半的那条丢弃，然后显示错误。点「重试」时，模型能看到已经发出的内容，不会把整段重新保存一遍 | `runReply` |
| 上下文 | 历史中角色的发言按同样的格式写回，帮助模型保持格式；用户发的表情包写成「[发来一个表情包：含义]」 | `context.ts` |

**额外 Token 成本**：格式说明约 300 字；可选表情包列表最多 24 个，每个约 6 字；历史中每条角色消息多出约 11 个字符的标记。没有增加任何额外的模型调用。

## 角色语言风格

在「编辑角色 → 聊天风格（可选）」中设置：

- 话量：少 / 适中 / 多
- 表达风格：跟随人设 / 简洁 / 活泼 / 温柔 / 冷淡 / 幽默
- 表情包：从不 / 偶尔 / 经常
- 亲密程度：自动 / 初识 / 熟悉 / 亲密
- 语言特点：自由填写

这些设置只影响说话方式。提示词里写明「与人设冲突时以人设为准」，没设置的项目不会写进提示词，避免所有角色套用同一个模板。

亲密程度选「自动」时，会结合人设里写的「与你的关系」和实际聊过的轮数来把握分寸：不到 6 轮、60 轮以内、60 轮以上，提示词分别不同。

旧角色没有这些字段时，表情包频率沿用原来的「允许使用表情包」开关。

## 表情包

- **来源**：只能由用户从相册或文件中添加。不引用任何外部网址，也不上传。
- **校验**：
  - 按文件头判断真实类型，只接受 PNG、JPEG、WebP 和 GIF。SVG、HTML 以及改了扩展名的文件会被拒绝。
  - 原文件不超过 5 MB，原图边长不超过 4096 px。
  - 图片必须能被浏览器正常解码。
- **处理**：静态图片缩小到 512 px 以内；GIF 保留原文件以保留动画，大小不超过 1.5 MB。
- **存储**：以 dataURL 存在本机 IndexedDB 的 `stickers` 表中。显示时只接受本机图片的 dataURL。
- **管理**：长按表情包可以设为常用、填写或修改含义、设置是否允许角色使用，或者删除。删除表情包不会删除聊天记录，相关消息显示为「表情包已删除」。
- **AI 使用**：
  - 只有写了含义并允许使用的表情包，才会以 `k1=开心转圈` 这样的短编号提供给模型。常用的排在前面，最多 24 个。
  - 模型输出的编号会和本次提供的列表核对，不在列表里的一律丢弃（演示中故意编造的 `k9` 就被丢掉了）。
  - 角色的表情包频率设为「从不」时，不向模型提供任何表情包。

## 诚实与边界

系统提示中写明了以下几点：

- 平时不必主动谈论技术细节；用户认真问到时，要诚实说明是 AI 扮演的角色。
- 不刻意让用户依赖角色，不劝用户疏远现实中的人。

不显示任何在线状态或已读回执。「正在输入」只在真的在生成回复时显示。
